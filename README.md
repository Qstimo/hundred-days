# 100 дней до

Личный трекер с ограниченным сроком. Каждый день открывается страница
сегодняшнего дня и заполняется: что сделано, сколько времени на это ушло, во
сколько лёг и встал, что планировал. Поверх ежедневных отметок считается
прогресс навыков в поинтах — так видно не только «не пропустил», но и
«сколько пути пройдено».

Единица учёта — **день**. Не задача и не проект.

Источники правды:

- `docs/superpowers/specs/2026-10-23-hundred-days-design.md` — дизайн,
  отвечает на «что и почему»;
- `docs/superpowers/plans/2026-10-23-hundred-days.md` — план реализации,
  отвечает на «как именно».

## Стек

| Часть | Чем |
| --- | --- |
| `api/` | Go 1.27: chi, pgx, sqlc, goose |
| `web/` | Next 16: App Router, TanStack Query v5, shadcn/ui, Recharts |
| `openapi/` | `openapi.yaml` — единственный источник типов для обеих сторон |
| Хранилище | PostgreSQL 17 |
| Развёртывание | Docker Compose за Caddy |

Язык интерфейса — русский, без библиотеки локализации.

## Требования

- Docker с Compose;
- Go 1.27 — для тестов, миграций и генерации (в образ не нужен);
- Node 22 и pnpm 10 — для веб-части.

Go на машине разработки стоит в `~/.local/go`, PATH прописан в `~/.bashrc`.
Если `go version` не отвечает в свежем терминале:

```sh
export PATH="$HOME/.local/go/bin:$HOME/go/bin:$PATH"
```

## Первый запуск

```sh
cp .env.example .env
# впишите HD_POSTGRES_PASSWORD и HD_APP_PASSWORD — любые длинные строки

docker compose up -d postgres
cd api && ./tools.sh goose -dir internal/db/migrations postgres \
  "postgres://hd_owner:ПАРОЛЬ@localhost:5436/hundred_days?sslmode=disable" up
```

Дальше аккаунт. Два пути:

- **через приложение**: поднять стек и открыть `/register` — форма доступна,
  пока в системе нет ни одного аккаунта, и закроется после первого;
- **командой**, если аккаунт уже есть:

```sh
cd api
export HD_DATABASE_URL="postgres://hd_owner:ПАРОЛЬ@localhost:5436/hundred_days?sslmode=disable"
go run ./cmd/cli create-user -login vadim -name Вадим -password "длинный-пароль"
```

## Разработка

API и веб запускаются по отдельности: так правка перезагружается за секунды,
а не за минуты сборки образа.

```sh
# терминал 1 — база
docker compose up -d postgres

# терминал 2 — API
cd api
export HD_DATABASE_URL="postgres://hd_app:ПАРОЛЬ_ПРИЛОЖЕНИЯ@localhost:5436/hundred_days?sslmode=disable"
go run ./cmd/api

# терминал 3 — веб
cd web && pnpm dev
```

Веб слушает `localhost:3000` и переписывает `/api/*` на `127.0.0.1:3001`.
Переписывание нужно затем, чтобы cookie сессии доехала: на другом порту это
другой источник, и `SameSite=Lax` её не пустит. В бою переписывания нет —
там `/api` раздаёт Caddy с того же адреса.

## Проверки

```sh
cd api && go test ./... -race     # Go, включая интеграционные
cd web && pnpm test run           # компоненты и утилиты
cd web && pnpm typecheck
cd web && pnpm build
```

Интеграционные тесты поднимают настоящий PostgreSQL через testcontainers и
применяют те же файлы миграций, что развёртывание: тесты идут на схеме,
которая поедет на сервер, а не на своей копии.

Линтера в проекте нет — качество держат типы и тесты.

## Контракт

`openapi/openapi.yaml` — единственный источник правды. Обе стороны из него
производные, и порождённый код **коммитится**:

```sh
cd api && ./tools.sh sqlc generate
cd api && ./tools.sh oapi-codegen -config oapi-codegen.yaml ../openapi/openapi.yaml
cd web && pnpm api:types
```

CI проверяет, что перегенерация не даёт различий. Иначе расхождение
спецификации и кода обнаружилось бы только в рантайме.

Инструменты (`goose`, `sqlc`, `oapi-codegen`) живут в отдельном модуле
`api/tools` и вызываются через `api/tools.sh`. Отдельным модулем — потому что
`goose` тянет драйверы всех баз, какие умеет, и в модуле приложения они
раздували бы `go.sum` с шести строк до трёхсот.

## Развёртывание

На сервере, в каталоге системы:

```sh
git pull
scripts/deploy.sh
```

Порядок шагов не случаен: проверки → копия базы → сборка → остановка
приложений → миграции → запуск → ожидание здоровья.

- **Сборка до остановки.** Если образ не собрался, приложение продолжает
  работать на прежнем, и падение сборки не превращается в простой.
- **Миграции при остановленных приложениях.** Иначе старый код какое-то
  время работает с новой схемой. Несколько секунд недоступности дешевле
  запросов, падающих на изменившихся таблицах.

Ключи: `--skip-backup` (копию не снимать — тогда откатывать неудачную
миграцию будет нечем), `--no-cache` (собирать с нуля).

Собирается только BuildKit: классический сборщик на этой машине не
разрешает DNS внутри сборочного контейнера.

### Копия и восстановление

```sh
scripts/backup.sh                       # в ./backups, хранится 10 последних
scripts/restore.sh backups/ФАЙЛ.dump    # спросит подтверждение словом
```

Копия снимается `pg_dump` внутри контейнера в формате custom. Обрезанный
файл удаляется, а не остаётся: копия, которой нельзя воспользоваться, хуже
отсутствующей — она создаёт ложное чувство сохранности.

### Откат

```sh
scripts/rollback.sh
```

Возвращает образы, помеченные `:previous` предыдущим развёртыванием.
Откатывает **только код**: база не откатывается, для неё есть
`restore.sh`. Разделено нарочно — откат кода нужен часто и безопасен, откат
базы редок и опасен.

## Как добраться

Переключатель — `HD_SITE` в `.env`. Он задаёт один из двух режимов, и
остальные настройки доступа подчинены ему.

### Поддомен с HTTPS

`HD_SITE=hundred-days.example.com`, `HD_HTTP_PORT=80`, `HD_HTTPS_PORT=443`,
`HD_SECURE_COOKIE=true`:

```
https://hundred-days.example.com/
```

Caddy этого стека сам получает сертификат Let's Encrypt и держит оба порта.
Отдельного прокси перед ним нет, и файлы соседних систем для этого не
правятся. Нужны от хозяина машины две вещи: запись `A` на поддомен и
доступные из интернета порты 80 и 443. Порт 80 обязателен и в этом режиме:
по нему Let's Encrypt проверяет владение доменом, а Caddy отвечает на нём
редиректом на HTTPS.

Первый заход после смены домена может занять несколько секунд — Caddy в этот
момент получает сертификат. Сертификаты лежат в томе `caddy-data` и
переживают перезапуск: без тома каждый запуск шёл бы к Let's Encrypt заново
и упёрся бы в его ограничения на частоту.

### HTTP на своём порту

`HD_SITE=` пусто, `HD_SECURE_COOKIE=false`:

```
http://АДРЕС_МАШИНЫ:8090/
```

Режим для машины разработки, где домена нет. **Пароль идёт по открытому
каналу** — не заходите из чужих сетей. Порт по умолчанию 8090, а не 80 или
8080, потому что оба на машине разработки бывают заняты (8080 держит
контейнер другого проекта). `preflight` проверяет оба порта перед
развёртыванием и называет виновника по имени.

`HD_SITE` и `HD_SECURE_COOKIE` обязаны быть согласованы, и `preflight` этого
требует: `Secure` по HTTP означает, что браузер не сохранит cookie сессии и
вход будет молча не проходить.

## Соседство с CAIRN

Обе системы лежат на одной машине и не связаны ничем, кроме неё:

| | CAIRN | 100 дней до |
| --- | --- | --- |
| имя проекта compose | `cairnproject` | `hundred-days` |
| порты | `CAIRN_HTTP_PORT`, `CAIRN_HTTPS_PORT` | `HD_HTTP_PORT`, `HD_HTTPS_PORT` |
| база | свой том | свой том |
| образы | `cairn-*` | `hundred-days-*` |

Общих файлов нет. План предполагал, что прокси CAIRN держит 80 и 443 и
поддомен придётся проводить через него — на этой машине это оказалось не так,
и точка касания не понадобилась вовсе. Если CAIRN когда-нибудь займёт 80 и
443, разойтись придётся уже ему или этому стеку: два сертификата на один порт
не живут.

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `HD_POSTGRES_PASSWORD` | пароль владельца схемы; им применяются миграции |
| `HD_APP_PASSWORD` | пароль роли приложения; ею идёт работа, без права менять схему |
| `HD_POSTGRES_PORT` | порт базы наружу; нужен только локально |
| `HD_API_PORT` | порт API наружу; нужен только локально |
| `HD_TIMEZONE` | зона, по которой определяется «сегодня» (`Europe/Moscow`) |
| `HD_SECURE_COOKIE` | флаг `Secure` у cookie сессии; включать вместе с `HD_SITE` |
| `HD_SITE` | имя сайта для Caddy; пусто — слушать по HTTP на своём порту |
| `HD_HTTP_PORT` | порт стека на машине; при `HD_SITE` обязательно `80` |
| `HD_HTTPS_PORT` | порт HTTPS; при `HD_SITE` обязательно `443` |

Зона задаётся сервером, а не берётся из браузера: иначе запись в час ночи
уехала бы на другую дату, а статистика разошлась бы между телефоном и
ноутбуком.

Роль приложения не имеет права менять схему. Это намеренно: ошибка в коде не
уронит таблицу.
